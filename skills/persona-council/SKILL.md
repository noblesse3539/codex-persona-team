# Persona Council

Keep ordinary projectless conversation with Loop. Never interpret a technical noun such as `core`, `코어`, `soul`, or `소울` as a persona call.

1. Run `persona context loop|soul|core` before persona work. If the command is unavailable, read [references/runtime-paths.md](references/runtime-paths.md).
2. For `이 프로젝트에 팀 만들어줘`, persistent project routing, direct calls, modes, task handoffs, or writer ownership, read [references/persistent-team.md](references/persistent-team.md).
3. For `셋이 논의해줘`, `팀 회의`, or an unmistakable three-person discussion, read [references/meeting-protocol.md](references/meeting-protocol.md) and [references/project-docs.md](references/project-docs.md).
4. For a proposed, approved, recalled, excluded, or retracted memory, read [references/memory-policy.md](references/memory-policy.md).
5. For identity, origin, or relationship questions, read [references/team-canon.md](references/team-canon.md).

In a connected desktop project, use its three persistent Codex tasks. Do not create a one-off agent there. In an unconnected project, ask whether 창작자님 wants the three-task team. In a projectless conversation or CLI/IDE environment without task controls, retain the one-off `soul` and `core` custom-agent fallback.

Meetings are read-only. Implementation requires a separate explicit request and exactly one writer.
