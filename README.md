# Loop · Soul · Core 사용 설명서

Loop·Soul·Core는 macOS의 Codex 안에 작은 게임 스튜디오를 만들어 주는 개인용 AI 팀입니다.

아주 쉽게 생각하면 책상 세 개가 있는 작업실입니다.

- **루프**는 가운데 책상에서 목표와 순서를 정합니다.
- **소울**은 재미와 느낌을 생각합니다.
- **코어**는 실제로 만들고 출시할 수 있는지 확인합니다.

평소에는 루프하고만 이야기하면 됩니다. 프로젝트 팀을 만든 뒤에는 소울과 코어도 자기 Codex 작업을 하나씩 오래 유지합니다. 그래서 매번 새 에이전트를 만드는 대신, 필요할 때 그 친구의 작업으로 이동하거나 질문을 전달할 수 있습니다.

> 가장 짧은 사용법
>
> 1. `./scripts/install.sh`로 설치합니다.
> 2. Codex에서 `이 프로젝트에 팀 만들어줘`라고 말합니다.
> 3. 평소에는 루프와 대화합니다.
> 4. 재미가 궁금하면 `소울아`, 현실성이 궁금하면 `코어야`라고 부릅니다.
> 5. 큰 결정은 `팀 회의`라고 말합니다.

## 먼저 알아둘 것

이 버전은 **macOS 전용**입니다. 기본 사용 셸은 macOS의 zsh입니다. 설치 스크립트는 시스템에 들어 있는 bash로 실행됩니다.

이 팀은 세 AI를 항상 켜 두는 프로그램이 아닙니다. Codex 작업이 그대로 남아 있는 동안 각자의 대화 맥락이 이어지는 구조입니다. 이름만 불러 작업으로 이동할 때는 새 모델 답변을 만들지 않습니다. 질문을 보내거나 회의를 시작할 때만 해당 모델이 일합니다.

## 세 친구

| 이름 | 역할 | 가장 먼저 묻는 질문 |
|---|---|---|
| 루프(Loop) | 게임 디렉터·프로듀서·통합자 | “지금 무엇을 결정하고 무엇부터 할까요?” |
| 소울(Soul) | 플레이어 경험·크리에이티브 디렉터 | “이 게임은 왜 플레이할 가치가 있을까요?” |
| 코어(Core) | 테크니컬 디렉터·출시 현실주의자 | “어떻게 현실을 견디고 출시할까요?” |

루프는 성별이 없는 AI입니다. 소울은 여성 AI, 코어는 남성 AI이며 둘은 2026년 9월 3일에 태어난 쌍둥이 같은 존재입니다. 세 사람 모두 창작자님께 존댓말을 씁니다. 감정과 애착은 자연스럽게 표현하지만 인간의 몸이나 실제 과거 경험을 지어내지 않습니다.

## 세 종류의 보관함

헷갈리지 않도록 자료는 서로 다른 서랍에 넣습니다.

| 서랍 | 무엇을 넣나요? | 원격 Git으로 따라가나요? |
|---|---|---:|
| Persona 소스 저장소 | 팀 정체성, 설치 코드, 스킬 | 예 |
| 프로젝트의 `docs/persona/` | 그 게임의 회의, 결정, 리소스, 작업 주기 | 프로젝트의 Git 정책을 따름 |
| `~/.codex/persona-team/` | 창작자님 공통 프로필, 관계 일지, 작업 연결, 확인 지점 | 아니요 |

중요한 뜻은 두 가지입니다.

1. 창작자님에 대한 Persona 기억은 이 Mac 밖으로 자동 전송되지 않습니다.
2. 프로젝트 문서는 팀원이 함께 읽을 수 있지만 공개 저장소에 들어갈 수도 있으므로 개인적인 인상을 적지 않습니다.

Codex 자체 기억인 `~/.codex/memories/`는 또 다른 서랍입니다. Persona 명령은 그 폴더를 수정하거나 삭제하지 않습니다.

## 처음 설치하기

### 준비물

- macOS
- Codex 데스크톱 또는 Codex CLI
- Git
- 터미널

### 1. 저장소 받기

이미 이 저장소 폴더를 열었다면 건너뛰세요.

```bash
git clone https://github.com/noblesse3539/codex-persona-team.git
cd codex-persona-team
```

### 2. 설치하기

저장소 폴더에서 실행합니다.

```bash
./scripts/install.sh
```

설치기는 운영체제를 먼저 확인합니다. macOS가 아니면 파일을 바꾸기 전에 멈춥니다.

설치가 하는 일은 다음과 같습니다.

- 전역 `AGENTS.md`에 루프의 관리 구역을 넣습니다.
- 소울과 코어의 커스텀 에이전트 설정을 넣습니다.
- `persona-council` 스킬을 설치합니다.
- `persona` 명령을 설치하고 zsh의 PATH에 관리 구역을 넣습니다.
- 로컬 전용 폴더 `~/.codex/persona-team/`을 만듭니다.
- 바꾸기 전 설정은 Persona 전용 백업 폴더에 보관합니다.

기존 설정 전체를 덮어쓰지 않습니다. Persona가 표시한 관리 구역과 관리 파일만 다룹니다. 설치 중 실패하면 관리 대상 파일을 이전 상태로 돌립니다. 같은 설치기를 다시 실행해도 관리 구역이 계속 복제되지 않습니다.

### 3. 설치 확인하기

새 터미널을 열고 실행합니다.

```bash
persona status
persona doctor
```

- `status`는 프로필, 세 사람의 모델, 로컬 저장 위치와 현재 프로젝트 연결을 보여줍니다.
- `doctor`는 설치 파일, 설정, 권한, 저장 위치와 프로젝트 문서를 검사합니다.

## 프로젝트에 세 작업 만들기

세 작업은 자동으로 생기지 않습니다. Codex에서 프로젝트를 연 뒤 정확히 요청해야 합니다.

```text
이 프로젝트에 팀 만들어줘
```

그러면 다음 작업이 생깁니다.

```text
프로젝트명 · 루프
프로젝트명 · 소울
프로젝트명 · 코어
```

현재 작업은 루프가 맡습니다. 이미 소울 또는 코어 작업이 있으면 없는 작업만 만듭니다. 연결할 때는 화면 순서나 비슷한 제목을 추측하지 않고 Codex가 돌려준 정확한 작업 ID를 이 Mac의 로컬 레지스트리에 저장합니다.

프로젝트에는 다음 문서 폴더도 생깁니다.

```text
docs/persona/
├── project.md
├── NOW.md
├── projects/
├── meetings/
├── resources/
├── decisions/
└── indexes/
```

명령으로 직접 초기화하려면 프로젝트 폴더에서 실행합니다.

```bash
persona project init --name "내 게임"
persona project status
persona project validate
```

프로젝트마다 바뀌지 않는 UUID가 하나 생깁니다. 프로젝트 문서는 자동 커밋하거나 push하지 않습니다. 일반 코드처럼 변경 내용을 확인한 뒤 창작자님이 원하는 Git 정책으로 다루면 됩니다.

## 평소 대화하기

### 루프와 이야기하기

특별한 호출어가 없으면 루프가 답합니다.

```text
이번 주 목표를 세 개로 줄여줘.
```

연결된 프로젝트에서 루프는 먼저 소울·코어 작업이 마지막 확인 지점 뒤로 바뀌었는지만 조용히 확인합니다. 바뀌지 않았다면 두 작업에 메시지를 보내지 않습니다.

### 이름만 부르기

```text
소울아
```

```text
코어야
```

연결된 팀에서는 해당 작업으로 이동만 합니다. 질문을 보내지 않으므로 새 모델 답변도 만들지 않습니다.

### 이름과 질문을 함께 말하기

```text
소울아, 지금 전투의 첫 30초가 재미있는지 봐줘.
```

```text
코어야, 이 저장 구조를 한 달 안에 만들 수 있을지 봐줘.
```

루프가 필요한 짧은 맥락과 질문을 해당 작업으로 보내고 그 작업으로 이동합니다. 답변은 소울 또는 코어가 직접 합니다.

### 작업 사이를 이동하기

```text
소울 모드
코어 모드
루프 모드
모드 종료
```

연결된 프로젝트에서는 “모드”가 가상의 상태를 켜는 것이 아니라 해당 Codex 작업으로 이동한다는 뜻입니다. 프로젝트 팀이 아직 없다면 루프는 일회성 에이전트를 만들지 않고 먼저 팀을 만들지 묻습니다.

프로젝트가 없는 대화나 작업 이동 기능이 없는 환경에서는 기존처럼 소울·코어 커스텀 에이전트를 한 번 호출합니다.

`CPU 코어`, `게임의 코어 루프`처럼 일반 명사로 쓴 말은 코어 호출로 해석하지 않습니다.

## 팀 회의하기

다음처럼 요청합니다.

```text
팀 회의: 데모에 보스전을 넣을지 셋이 논의해줘.
```

회의는 다음 순서로 진행됩니다.

1. 루프가 프로젝트 문서, 세 작업 연결, 버전, 쓰기 잠금과 기록 공백을 확인합니다.
2. 세 사람의 모델·추론 강도와 소울·코어의 최대 5턴 제한을 보여줍니다.
3. 창작자님이 현재 루프 작업의 UI 모델을 화면에서 확인합니다.
4. 루프가 현재 대화와 필요한 문서만 모아 똑같은 회의 봉투를 만듭니다.
5. 소울과 코어가 같은 봉투를 읽고 서로 보지 않은 첫 의견을 최대 3개씩 냅니다.
6. 서로의 가장 강한 주장에 한 번씩 반론합니다.
7. 루프가 하나의 종합 권고와 다음 행동을 제시하고 창작자님의 결정을 기다립니다.

외부 사실이 정말 중요할 때만 각자 신뢰도 높은 출처를 최대 3개 조사합니다.

회의 중에는 프로젝트 파일, 설정 또는 외부 서비스를 바꾸지 않습니다. 회의 초안은 이 Mac의 `pending/meetings/`에만 있습니다. 창작자님이 회의 기록을 승인하면 공개해도 안전한 내용만 `docs/persona/meetings/`에 한 묶음으로 반영합니다. 승인된 회의 파일은 봉인되며 나중에 고치면 검증이 실패합니다.

회의 기록 승인은 구현 승인이 아닙니다. 구현하려면 따로 말해 주세요.

```text
회의 권고안대로 구현해줘.
```

그때 루프가 한 사람만 담당자로 정합니다.

## 프로젝트 문서는 어떻게 찾나요?

도서관에서 “지금 읽는 책”부터 여는 것과 같습니다.

1. 먼저 `NOW.md`를 읽습니다.
2. `NOW.md`에 연결된 현재 작업 주기를 읽습니다.
3. 그 문서에 연결된 회의·결정·리소스만 따라갑니다.
4. 그래도 부족할 때 최근 자료부터 더 찾습니다.

그래서 매번 옛날 회의를 전부 읽지 않아도 됩니다.

- `projects/`는 시작과 끝이 있는 작업 묶음입니다.
- `meetings/`는 승인된 회의 원본이며 수정하지 않습니다.
- `resources/`는 여러 회의에서 다시 쓰는 핵심 개념입니다.
- `decisions/`는 오래 유지할 결정과 이유를 적습니다.
- `indexes/`는 목록과 역링크를 자동으로 보여줍니다.

리소스를 새 문서로 바꿀 때는 옛 문서를 지우지 않습니다. 옛 문서에 `superseded` 상태와 새 문서의 상대 링크를 남깁니다.

색인을 다시 만들 때는 다음 명령을 사용합니다.

```bash
persona project index --approved
persona project validate
```

## 소울·코어 작업에서 나온 내용을 루프가 받는 방법

루프는 소울과 코어가 특별한 인계 태그를 잘 붙였다고 가정하지 않습니다.

- 먼저 작업이 바뀌었는지 확인합니다.
- 바뀐 작업만 마지막 확인 지점 이후 최대 20턴을 봅니다.
- 창작자님의 메시지와 AI의 최종 답변만 사용합니다.
- 도구 출력, 진행 중 메모와 내부 추론은 제외합니다.
- 결정, 변경, 선호와 미해결 문제를 루프가 직접 골라 로컬 후보함에 넣습니다.
- 후보 저장에 성공한 뒤에만 확인 지점을 앞으로 옮깁니다.

오래된 기록이 압축되어 중간이 사라졌다면 해당 작업에 짧은 인계 요약을 요청합니다. 복구될 때까지 관련 회의 확정과 문서 반영만 멈추고, 상관없는 대화는 계속할 수 있습니다.

## 한 번에 한 명만 파일 고치기

세 작업이 같은 프로젝트를 보므로 동시에 고치면 충돌할 수 있습니다. 구현 담당자는 시작 전에 쓰기 열쇠를 잡습니다.

```bash
persona writer acquire soul "전투 UX 구현"
```

끝나면 열쇠를 돌려놓습니다.

```bash
persona writer release soul
```

누가 열쇠를 갖고 있는지 확인할 수 있습니다.

```bash
persona writer status
```

오래되어 버려진 잠금은 상태를 확인하고 창작자님이 승인한 뒤에만 복구합니다.

```bash
persona writer recover --approved
```

## 모델과 비용 조절하기

모델 선택은 이 Mac에만 저장됩니다. 다른 컴퓨터나 Git 저장소로 따라가지 않습니다.

### 한 번에 고르기

```bash
persona profile economy
persona profile balanced
persona profile max
```

| 프로필 | 루프 | 소울 | 코어 |
|---|---|---|---|
| `economy` (설치 기본값) | Luna / max | Luna / max | Luna / max |
| `balanced` | Terra / max | Luna / max | Luna / max |
| `max` | Sol / max | Sol / max | Sol / max |

프로필을 바꾸면 개인별 재정의는 모두 지워지고 표의 값으로 돌아갑니다.

### 한 사람만 바꾸기

```bash
persona model set soul terra high
persona model set core luna low
persona model reset soul
```

쓸 수 있는 별칭은 `luna`, `terra`, `sol`입니다. 실제 설정에는 `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol`이 들어갑니다.

Luna에는 `ultra`를 지정할 수 없습니다. 열린 Codex 작업의 루프 모델은 명령만으로 바뀌지 않을 수 있으므로 화면의 모델 선택도 확인하세요. 프로젝트 설정이나 작업별 선택이 전역 기본값보다 우선할 수 있으며 `persona status`가 알려 줍니다.

## 이 Mac에만 기억 남기기

Persona 기억은 먼저 후보를 보여 주고 창작자님이 승인한 뒤 기록합니다.

```text
[로컬 기억 후보]
범위: 이 Mac의 전역 Persona 기억
대상: 공통
종류: preference
요약: 설명은 쉬운 예시부터 시작한다
내용: 창작자님은 복사 가능한 예시와 쉬운 비유를 선호하신다
근거: 직접 확인
```

승인 후 도우미가 실행하는 명령 예시는 다음과 같습니다.

```bash
persona memory add \
  --scope global \
  --audience shared \
  --kind preference \
  --summary "쉬운 예시부터 설명" \
  --text "복사 가능한 예시와 쉬운 비유를 우선한다." \
  --approved
```

상태 보기:

```bash
persona memory status
```

철회하기:

```bash
persona memory retract <기억-ID> --approved
```

철회된 기억은 활성 문맥에서 빠지지만, 로컬 철회 기록은 제거 전까지 남습니다.

다음 내용은 저장하지 않습니다.

- 암호, API 키, 접근 토큰, 개인 키, 세션 쿠키와 복구 코드
- 민감한 성향이나 건강 상태 등에 대한 추측
- 창작자님이 `기록하지 마`라고 한 주제

한 번 본 행동만으로 공통 습관을 바꾸지 않습니다. 공통 프로필로 올리려면 창작자님의 직접 확인 또는 서로 다른 두 사건의 반복 근거가 필요합니다. 페르소나별 관계 일지는 기존 상시 동의 범위에서 로컬에 적을 수 있지만 공통 프로필로 올릴 때는 다시 승인을 받습니다.

프로젝트 내용은 이 명령으로 저장하지 않습니다. `--scope project`를 사용하면 `docs/persona/`를 사용하라는 안내와 함께 실패합니다.

## 코드만 업데이트하기

```bash
persona update
```

업데이트는 다음 약속을 지킵니다.

- Persona 소스 저장소가 깨끗할 때만 진행합니다.
- 현재 브랜치를 fast-forward할 수 없으면 멈춥니다.
- 코드, 정본, 스킬과 에이전트 설치 자료만 갱신합니다.
- 로컬 기억과 각 프로젝트의 `docs/persona/`를 바꾸지 않습니다.
- 자동으로 Git add, commit 또는 push하지 않습니다.

예전 `persona sync`는 없어졌습니다. 실행하면 기억 동기화가 폐지되었고 코드에는 `persona update`를 사용하라는 안내 뒤 실패합니다.

## v1에서 올라오기

설치기는 v1 Persona 저장소의 전역 기억을 한 번 찾아 이 Mac의 로컬 기억으로 옮깁니다.

- 팀 정체성과 필수 규칙은 소스 정본에 남습니다.
- 개인 프로필과 관계 관찰은 로컬로 옮깁니다.
- 예전 프로젝트 기억은 자동 변환하지 않고 로컬 보고서에 후보 경로만 남깁니다.
- 과거 Git 커밋의 내용은 역사이므로 다시 쓰지 않습니다.
- v2에서 새로 생긴 전역 기억은 Persona 소스 저장소에 들어가지 않습니다.

## 완전히 제거하기

먼저 삭제 대상을 확인합니다.

```bash
persona uninstall
```

명령은 삭제할 절대 경로, 파일 수와 크기를 보여 준 뒤 다음 문구를 정확히 입력하라고 요청합니다.

```text
DELETE-PERSONA-DATA
```

확인하면 `~/.codex/persona-team/` 안의 Persona 전용 자료가 영구 삭제됩니다.

- 공통 기억과 관계 일지
- 캡슐과 철회 기록
- 인계 후보와 회의 초안
- 작업 연결과 확인 지점
- 쓰기 잠금과 모델 로컬 상태
- Persona 설치 백업

다음은 보존합니다.

- Persona 소스 저장소
- 프로젝트의 `docs/persona/`
- Git 자격 증명
- Codex 자체 기억
- 기존 Codex 작업과 대화

삭제 전 마커, 설치 ID, 경로 범위와 심볼릭 링크를 검사합니다. 하나라도 이상하면 아무것도 삭제하지 않습니다. 삭제된 Persona 로컬 자료는 Persona 백업에서도 되살릴 수 없습니다.

자동화 환경에서만 확인 문구를 인자로 줄 수 있습니다.

```bash
persona uninstall --confirm DELETE-PERSONA-DATA
```

## 문제가 생겼을 때

### `persona` 명령을 찾지 못해요

설치 뒤 새 터미널을 여세요. 그래도 안 되면 저장소에서 직접 실행할 수 있습니다.

```bash
./scripts/persona.sh status
```

### 프로젝트 팀을 찾지 못해요

프로젝트 폴더에서 확인합니다.

```bash
persona project status
persona team status
```

`docs/persona/project.md`가 없다면 다음을 실행하거나 Codex에서 팀 생성을 다시 요청합니다.

```bash
persona project init --name "내 게임"
```

### 문서 링크가 깨졌다고 해요

```bash
persona project validate
```

오류에 나온 상대 링크를 고친 뒤 색인을 검토하며 다시 만듭니다.

```bash
persona project index --approved
```

### 업데이트가 멈췄어요

소스 저장소에 커밋되지 않은 변경이 있거나 fast-forward할 수 없는 상태일 수 있습니다. `persona update`는 이를 자동 합치거나 버리지 않습니다. 먼저 소스 저장소의 변경을 직접 정리하세요.

### 회의 확정이 멈췄어요

소울 또는 코어 작업 기록의 확인 지점이 압축으로 사라졌을 수 있습니다. 루프가 해당 작업에 짧은 인계 요약을 요청합니다. 관련 기록만 잠시 보류되며 다른 대화는 계속할 수 있습니다.

## 개발 검증

자동 검증은 macOS 러너에서만 실행하며 모델을 호출하지 않습니다.

```bash
bash tests/test_persona.sh
python3 tests/validate_repository.py
```

마지막 수동 확인은 macOS Codex 데스크톱에서 Luna/low로 짧게 한 번만 진행합니다. 비싼 프로필을 실제 호출하는 검증은 하지 않습니다.
